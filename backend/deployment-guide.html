System Overview

Agrovia V0.1 is an offline-first agricultural digital ecosystem tailored for Indian farmers, consisting of:

📱 Flutter Application
Cross-platform mobile app with on-device AI inference, glassmorphism UI, and offline sync capabilities
🖥️ NestJS Backend
Modular REST API with JWT auth, multilingual NLU, market intelligence, and DPDP compliance
🗄️ PostgreSQL Database
Relational data store managed via Prisma ORM with full schema migrations
🐳 Docker Container
Multi-stage production build with Node 18 Alpine and optimized layer caching

Architecture Highlights

  • Dual-Tier AI: On-device TensorFlow Lite inference + asynchronous cloud CNN verification
  • Offline-First: Client-side sync queue with exponential backoff retry mechanism
  • Vernacular Support: Saanvi voice assistant with Hindi, Marathi, Telugu, Tamil, and English NLU
  • DPDP Compliance: Data export and right-to-be-forgotten user purge endpoints
  • Production Hardened: 6/6 backend unit tests passing, 3/3 Flutter tests passing, 0 static analysis issues

Local Development Setup

1. Clone Repository

Terminal
git clone https://github.com/your-org/agrovia.git
cd agrovia

2. Backend Setup

Terminal
cd backend
npm install
cp .env.example .env

Edit .env with your local configuration:

DATABASE_URL="postgresql://postgres:postgres@localhost:5432/agrovia?schema=public"
JWT_SECRET="your-strong-secret-key-min-32-chars"
PORT=3000

3. Database Initialization

Terminal
# Start PostgreSQL (if not running)
# Then run Prisma migrations
npx prisma migrate dev --name init
npx prisma generate

4. Start Backend Server

Terminal
npm run start:dev

Backend API will be available at http://localhost:3000

5. Flutter Application Setup

Terminal
cd ../app
flutter pub get
flutter analyze

6. Run Flutter App

Android/iOS
flutter run
Web (for testing)
flutter run -d chrome
⚠️ Firebase Configuration
Before running the app, configure Firebase by placing google-services.json (Android) and GoogleService-Info.plist (iOS) in their respective platform directories. The backend currently uses mock Firebase authentication for local development.

Docker Deployment

Using Docker Compose (Recommended)

The easiest way to run the complete backend + database stack:

Terminal
docker-compose up -d

This starts:

  • PostgreSQL 15 on localhost:5432
  • NestJS Backend on localhost:3000

Building Backend Image Manually

Terminal
cd backend
docker build -t agrovia/backend:latest .
docker run -p 3000:3000 \
  -e DATABASE_URL="postgresql://postgres:postgres@host.docker.internal:5432/agrovia" \
  -e JWT_SECRET="production-secret-key" \
  agrovia/backend:latest

Docker Compose Configuration

The docker-compose.yml at the repository root defines:

version: '3.8'
services:
  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=postgresql://postgres:postgres@db:5432/agrovia?schema=public
      - JWT_SECRET=production-hardened-strong-secret-key-42
      - PORT=3000
    depends_on:
      - db
    restart: unless-stopped

  db:
    image: postgres:15-alpine
    environment:
      - POSTGRES_USER=postgres
      - POSTGRES_PASSWORD=postgres
      - POSTGRES_DB=agrovia
    ports:
      - "5432:5432"
    volumes:
      - agrovia_pgdata:/var/lib/postgresql/data
    restart: unless-stopped

volumes:
  agrovia_pgdata:
💡 Production Environment Variables
Replace JWT_SECRET and database credentials with secure values for production. Use Docker secrets or a secrets manager (AWS Secrets Manager, GCP Secret Manager) for sensitive configuration.

Example: Google Cloud Run Deployment

1. Build and push Docker image
gcloud builds submit --tag gcr.io/your-project-id/agrovia-backend
2. Deploy to Cloud Run
gcloud run deploy agrovia-backend \
  --image gcr.io/your-project-id/agrovia-backend \
  --platform managed \
  --region asia-south1 \
  --allow-unauthenticated \
  --set-env-vars DATABASE_URL="postgresql://..." \
  --set-env-vars JWT_SECRET="..." \
  --memory 512Mi \
  --max-instances 10

Environment Variables Checklist

  • DATABASE_URL — PostgreSQL connection string
  • JWT_SECRET — Secret key for signing access tokens (min 32 chars)
  • PORT — Server listen port (default 3000)
  • NODE_ENV — Set to production

Running Migrations

Production migration
cd backend
npx prisma migrate deploy
⚠️ Migration Safety
Always test migrations on a staging database first. Use prisma migrate deploy (not migrate dev) in production to apply existing migrations without generating new ones.

Connection Pooling

For production workloads, use a connection pooler like PgBouncer to manage database connections efficiently:

# Example connection string with PgBouncer
DATABASE_URL="postgresql://user:pass@pgbouncer-host:6432/agrovia?pgbouncer=true"

Backup Strategy

  • Automated Daily Backups: Enable on your managed database provider
  • Point-in-Time Recovery: Recommended retention: 7-30 days
  • Manual Backup: pg_dump agrovia > backup.sql

CI/CD Pipeline

GitHub Actions Workflow

The repository includes .github/workflows/ci.yml with three jobs:

1️⃣ backend-test
Installs dependencies, runs oxlint and vitest on Node 20
2️⃣ app-test
Runs flutter analyze and flutter test with Flutter 3.x stable
3️⃣ docker-build
Builds Docker image with buildx caching (gated behind backend-test)

Triggering the Pipeline

The CI pipeline runs automatically on:

  • Push to main or develop branches
  • Pull requests targeting main or develop

Adding Deployment Step

To auto-deploy on successful builds, add a fourth job:

  deploy:
    name: Deploy to Cloud Run
    runs-on: ubuntu-latest
    needs: [backend-test, app-test, docker-build]
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v1
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}
      - name: Deploy
        run: |
          gcloud run deploy agrovia-backend \
            --image gcr.io/${{ secrets.GCP_PROJECT_ID }}/agrovia-backend:latest \
            --region asia-south1
💡 Secrets Configuration
Store sensitive values like GCP_SA_KEY, JWT_SECRET, and DATABASE_URL in GitHub repository secrets (Settings → Secrets and variables → Actions).

Security Checklist

  • ✅ JWT Secret: Use a cryptographically secure random string (min 32 characters)
  • ✅ Database Credentials: Never commit passwords to git; use environment variables or secrets manager
  • ✅ HTTPS Only: Enforce TLS 1.2+ on all production endpoints
  • ✅ CORS Configuration: Restrict allowed origins to your app domains only
  • ✅ Rate Limiting: NestJS Throttler is already configured; tune limits per endpoint
  • ✅ Prisma Client: Generated with --no-engine to reduce attack surface
  • ✅ Dependency Audits: Run npm audit regularly and apply security patches
  • ✅ Container Scanning: Use Trivy or Snyk to scan Docker images for vulnerabilities
  • ✅ Firebase Rules: Lock down Firestore/Storage access with proper security rules
  • ✅ DPDP Compliance: Test data export and purge endpoints before production launch

Performance Optimization

Backend

  • Enable response compression: app.use(compression())
  • Cache frequent queries with Redis or in-memory LRU cache
  • Use Prisma query optimization: select only needed fields, avoid N+1 queries
  • Implement pagination on /vision/history and /connect/feed

Flutter App

  • Enable code minification and obfuscation in release builds
  • Use const constructors wherever possible to reduce widget rebuilds
  • Lazy-load screens with GoRouter deferred loading
  • Compress images and use WebP format for assets
  • Profile with flutter run --profile and DevTools to identify bottlenecks

Database

  • Add indexes on frequently queried columns: userId, createdAt
  • Use EXPLAIN ANALYZE to optimize slow queries
  • Consider read replicas for analytics and reporting queries

Troubleshooting Common Issues

Backend won't start

Error: UnknownDependenciesException: Nest can't resolve dependencies

Solution: Ensure ConfigModule.forRoot({ isGlobal: true }) is imported in AppModule

Prisma migration fails

Error: P1001: Can't reach database server

Solution: Check DATABASE_URL connection string format and database server accessibility

Flutter build fails on iOS

Error: CocoaPods not installed

Solution: Run sudo gem install cocoapods then cd ios && pod install

Docker image size too large

Issue: Image exceeds 500MB

Solution: The multi-stage Dockerfile already optimizes this. Ensure node_modules and dist are not duplicated in final layer

High database connection count

Issue: Running out of PostgreSQL connections

Solution: Configure Prisma connection pool: connection_limit=10 in DATABASE_URL, or add PgBouncer
